# 用户反馈与偏好 — UI/交互

**Date**: 2026-08-15
**Category**: feedback
**Source**: conversation

## 核心偏好（多次强调）

1. **UI 必须基于开源生态风格**："不是在开源基础上进行完善的，UI特别难看"——要复用 DSH/生态的视觉语言（`--dsw-*` token），不要自创配色；不要 emoji，用线性 SVG 图标
2. **精简优先**："不需要搞那么复杂，UI把最基础的做好即可，我们看核心功能"——功能聚焦：SSH 连接 → 资源管理器 + 终端 + 编辑保存
3. **不要两个资源管理器**：与 better-sidebar 并存时只保留一个管理器（用 better-sidebar 的框架）
4. **稳定性 > 功能**："点击相关按钮容易崩溃，浏览器容易无响应"——优先修 bug（observer 循环、轮询、竞态）
5. 顶部工具栏多余（与中间连接 UI 重复）→ 已删除，连接操作收到底部状态栏

## 工作方式偏好

- 先调研分析、思考清楚再动工
- 保存记忆、更新进度（super-memory 流程）
- 最终目标明确后直接推进核心功能，不做过度设计

## 当前 UI 状态（2026-08-15）

- 右侧工作台：explorer（远程树/主机列表）+ 编辑器 + 底部终端 + 蓝色状态栏（主机下拉/连接/断开/新终端）
- 默认宽度 640px（可拖 400-1000）
- 全部 DSW token 主题化
- 入口行为：装 better-sidebar → 打开其「远程 IDE」tab；否则独立面板
